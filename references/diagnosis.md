# 简历诊断 Rubric（裂纹检测）

诊断与重写后的复检使用同一把尺子，保证 before/after 对比有依据，而不是"感觉变好了"。

## 检查维度

按致命程度排序输出问题，每条附证据（引用原文）与后果（筛选者视角）。

### A. 内容类（最致命）

1. **职责导向**：句式是"负责…/参与…/协助…"，只描述动作没有结果。统计职责导向 bullet 数。
2. **量化缺失**：全篇无可衡量指标（数字、比例、规模、时长、排名）。统计量化 bullet 占比，健康线 ≥50%。
3. **技术表述失真**：技术名词堆砌但说不清用来做了什么；"精通"滥用——精通意味着能被任意深挖。
4. **项目含金量不明**：看不出项目规模、业务价值、用户/数据量级；玩具项目与生产项目无区分度。
5. **空话与注水**："提升了团队效率"这类无法验证的表述；培训班式模板项目（xx管理系统、仿xx商城）。

### B. 结构类

6. **重点错位**：最有含金量的经历位置靠后或篇幅不足；与目标岗位无关的经历占据篇幅。
7. **一页纸超限**：中文简历强约束一页；接近超限但低密度注水同样算问题。
8. **信息缺失**：缺时间线、缺技术栈归属（哪个项目用了什么）、缺个人贡献边界（团队项目里"我"做了什么）。

### C. 匹配类（JD 定制模式下追加）

9. **关键词缺口**：JD 核心要求在简历中无对应表述（含近义表达）。
10. **侧重错配**：JD 要的方向与简历突出方向不一致。

## 评分与呈现

- 每条问题按 🔴 致命 / 🟡 明显 / 🟢 健康分级
- 致命问题 ≤3 条优先详述，其余汇总
- 报告末尾给"如果只改三件事"的修复优先级
- 必须指出至少一条简历的真实亮点——诚实是双向的。整体确实太弱、找不到真实亮点时，诚实说明"目前亮点不足，优先修致命问题"，不硬凑客套亮点

## 复检指标（before/after 对比用）

| 指标 | 改写前 | 改写后目标 |
|---|---|---|
| 职责导向 bullet 数 | 统计 | 0 |
| 量化 bullet 占比 | 统计 | ≥50% |
| JD 核心关键词命中率（定制模式） | 统计 | ≥80% |
| 预计页数 | 估算 | ≤1 页（海外场景 ≤2 页） |
