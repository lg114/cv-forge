# 措辞规范

改写每条内容时用的操作标准。**规则与边界以 SKILL.md 为准**——本文件只提供可照抄的对照表，不另立规则，也不放宽 SKILL.md 第 2 步的事实红线。

## 动词与成果强度分档

同一个动作可以用不同强度的词描述。**用哪一档由素材依据决定，不由期望决定**：改写前先定位素材能支撑的档位，只允许使用该档及以下的动词。

| 档 | 典型动词 | 用这一档的前提（须能在原文或用户确认中找到） | 不满足时 |
|---|---|---|---|
| 1 协助 / 参与 | 参与、协助、配合、支持 | 能指出本人在其中交付的**具体产物**，哪怕很小 | 连产物都说不出 → 只写本人做过的动作，不写这段经历的整体结果 |
| 2 负责 / 执行 | 负责、完成、实现、开发、编写、独立完成 | 能指出**范围边界**：这件事由本人交付，并能说出范围多大 | 说不出边界 → 降回第 1 档 |
| 3 主导 / 牵头 | 主导、牵头、推动、重构 | 能指出本人是**决策者**（方案由本人定 / 资源由本人协调），并能说明**协作规模**（几人、哪些角色） | 说不出决策权或协作规模 → 降回第 2 档 |
| 4 从 0 到 1 / 定义 | 从 0 到 1 搭建、定义、建立 | 能指出**此前不存在**，并能说明建成后的使用范围 | 说不出「此前没有」→ 降回第 3 档；说不出使用范围 → 降回第 2 档 |

**四条纪律**

1. **只能降档，不能跳档。** 素材只支撑第 1 档时，不能因为想写得漂亮就跳到第 3 档——与 SKILL.md 第 2 步事实红线同源，不是本文件另立的规则。
2. **同一条 bullet 内部必须同档。** 动词说「主导」，同一句里却没有任何范围或协作信息，读的人会立刻感到不匹配。动词强度要与句子其余部分的信息量一致。
3. **同一段经历的不同 bullet 可以处在不同档，整段不能统一升档。** 人倾向于把整段经历按最高档描述，这是最常见的夸大来源。
4. **团队成果有上限。** 账本里 `owner` 为团队时，动词可以描述本人做的动作，但不能用第 3、4 档描述结果；结果归属见 [事实账本规范](fact-ledger.md)。

> ✗ 原文只有「配合完成季度运营方案」→ 改后「主导季度运营方案，覆盖 3 条业务线」——档位从 1 跳到 3，且「3 条业务线」原文没有，同时违反事实红线 #2
> ✓ 原文「配合完成季度运营方案，负责其中渠道预算部分」→「完成季度运营方案的渠道预算部分」——原文给了具体产物，第 2 档可辩护

## 套话黑名单与替换方向

**替换只做词面，不改变事实**：替换方向里的每一项都必须是原文已有的信息。原文没有的，只能删除或列入「建议补充」，**不得借套话"补"出来**——那是事实红线管的事，不是措辞问题。

| 套话 | 问题 | 替换方向 |
|---|---|---|
| 负责…工作 / 参与了…项目 / 配合完成… | 只有岗位名，没有产出 | 写出本人交付的产物或负责的范围；原文没有这些信息时，按上文分档表降到素材能支撑的档位，并把缺口列入「建议补充」 |
| 具备良好的沟通能力 / 学习能力强 / 工作认真负责 / 抗压能力强 | 自评，无法验证 | 删掉；若确有一条经历能证明它，改写那条经历本身 |
| 熟练使用 Office / 熟悉计算机操作 / 英语良好 | 不构成区分度 | 删掉，或具体到经得起追问的层次 |
| 推进 / 跟进 / 对接 / 赋能 / 闭环 / 抓手 | 过程词，读完不知道本人做了什么 | 换成本人实际做的动作 |
| 完成 XX 系统上线 / 实现 XX 功能 | 看不出本人角色，读者分不清是本人做的还是团队做的 | 补上本人角色——这属于补事实，原文说不出角色时列入「建议补充」 |

**与优化力度的关系**：黑名单替换属于「删冗词」，各档力度都可做。但**整条要点除了套话别无内容时，删它属于删要点**，只在深度档按 SKILL.md「优化力度的边界」的弱要点标准执行；轻度、标准档只能替换词面，把该条列入「建议补充」交用户决定。

## 按资历层级的措辞侧重

**层级从素材推断，不追问**：按最早一段经历到现在的跨度、以及素材里有没有管理 / 决策 / 带人的描述判断。推断不出时按通用处理，不猜也不问。

**本节只调整措辞侧重**——一条 bullet 该强调什么性质的信息、用哪一类动词。**排序与显眼度以 SKILL.md「排序与显眼度」为唯一出处**，本节不定义谁排在前；事实红线在任何层级都不放松。

| 层级 | 证据重心 | 措辞上强调什么 | 常见错配 |
|---|---|---|---|
| 应届 / 在校 | 学习速度与可迁移性 | 把陌生领域学到能用的路径；课程 / 竞赛 / 开源里的具体产出；与岗位相关的最小可用经验 | 硬凑管理经验；把课程作业写成「项目负责人」 |
| 初级（约 3 年内） | 独立交付 | 从需求到上线的闭环；独立完成的完整任务；踩过并解决的坑 | 只罗列参与过的项目名，看不出本人独立做过什么 |
| 资深（约 5 年以上） | 范围与影响 | 负责的范围（团队规模、系统量级、业务体量）；做过的决策（定了什么方案、否了什么）；影响面（被谁采用）；带人（培养了谁、建立了什么机制） | 仍在写「我写了某模块的代码」——除非它支撑一个更大的判断 |
