# 示例：从输入到交付

本文件展示 CV Forge 处理一份简历片段的完整过程。数据纯属虚构，仅用于演示规则落地后的输出形态。

## 一、输入素材

用户贴入以下简历片段，未提供 JD，优化力度取缺省值（标准）。

```
陈明
手机：138-0000-1234
邮箱：chenming@example.com

教育背景
浙江大学 · 计算机科学与技术 · 本科  2018.09 – 2022.06

工作经历
杭州云启科技有限公司 · 后端开发工程师  2022.7 – 至今

- 参与了公司 2 个核心业务模块的后端开发工作
- 负责日常需求沟通与跨部门协作
- 优化了系统性能，接口响应从 800ms 降到 200ms
- 参与 15+ 次代码评审及线上问题排查

技能
Java, Spring Boot, MySQL, Redis, Git, Linux
```

**素材中可识别的典型问题**：

| 要点 | 问题 |
|---|---|
| 第 1 条 | 动词层级偏低（「参与」= 第 1 档），有数字但埋在句中 |
| 第 2 条 | 套话——只有过程词，看不出本人交付了什么 |
| 第 3 条 | 有数字但埋在句尾，「系统性能」过于笼统 |
| 第 4 条 | 「参与」+ 无产物无结果，属弱要点（深度档可删） |

## 二、三档优化力度对比

同一段素材分别按轻度 / 标准 / 深度处理，对比每条要点的改写差异。

### 第 1 条——动词层级修正

| 力度 | 改写 | 改了什么 |
|---|---|---|
| 轻度 | 参与公司 2 个核心业务模块的后端开发 | 删「了」「工作」冗词；动词和数字不动 |
| 标准 | 独立开发 2 个核心业务模块后端 | 「参与」→「独立开发」（第 1 档 → 第 2 档）；数字「2 个」前置于动词后 |
| 深度 | 同标准 | 措辞已到位，无需进一步调整 |

### 第 2 条——套话替换

| 力度 | 改写 | 改了什么 |
|---|---|---|
| 轻度 | 负责日常需求沟通与跨部门协作 | 仅删「了」；套话保留（轻度不删内容） |
| 标准 | 对接产品与运营团队需求，协调完成系统联调 | 过程词换成本人实际动作；「跨部门」具体化为协作对象 |
| 深度 | 同标准 | 信息已充分 |

### 第 3 条——数字前置与收窄表述

| 力度 | 改写 | 改了什么 |
|---|---|---|
| 轻度 | 优化系统性能，接口响应从 800ms 降到 200ms | 仅删「了」；数字保留原位 |
| 标准 | 核心接口响应时间从 800ms 优化至 200ms | 「系统性能」收窄到「核心接口响应时间」；数字前置，结果前置 |
| 深度 | 同标准 | 数字已到位，表述已具体 |

### 第 4 条——弱要点处理

| 力度 | 改写 | 改了什么 |
|---|---|---|
| 轻度 | 参与 15+ 次代码评审及线上问题排查 | 仅删冗词；动词不动 |
| 标准 | 参与 15+ 次代码评审，协助排查线上问题 | 拆分并列结构，补充协作方式；仍为第 1 档 |
| 深度 | **删除** | 满足弱要点标准：整条只有职责陈述、无结果性表述，且与第 3 条（系统优化）高度重复，信息增量为零 |

矩阵精简版（仅展示已采取措施、关键硬缺口、易误判为已满足的要求）：

## 四、自检行示例

以上述标准档交付为例，自检行落在输出最后一行：

```
自检：数字 4 处逐句比对（见「已修改」表）；姓名 / 组织 / 学历 / 日期 / 电话共 10 处逐字未动；定位号 4 个无重复——未发现不合规。
```

各项计数的来源：

- **数字 4 处**：「2 个」（第 1 条）、「800ms」「200ms」（第 3 条）、「15+」（第 4 条）——均与原文逐字一致
- **姓名 / 组织 / 学历 / 日期 / 电话共 10 处**：姓名（陈明）、组织（杭州云启科技有限公司、浙江大学）、学历（计算机科学与技术、本科）、日期（2018.09、2022.06、2022.07、至今）、电话（138-0000-1234）——共 10 处逐字未动
- **定位号 4 个**：标准档保留全部 4 条要点
