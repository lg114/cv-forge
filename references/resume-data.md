# 简历数据规范

在事实账本之后建立一份内部结构化简历数据，作为 Markdown、PDF 和可选 JSON/YAML 导出的唯一内容源。它是生成中间层，不要求用户使用固定输入格式。

## 模块

- `identity`：姓名、联系方式、链接。
- `headline`：求职意向或个人概览；没有事实依据时可为空。
- `experience[]`：每段工作、项目或实习；含稳定 `id`、时间（`原始值` + `展示格式`）、组织、角色和 `bullets[]`。
- `education[]`、`skills[]`、`certifications[]`、`awards[]`、`languages[]`：只在原文有事实时出现。
- 每个 `bullet` 含稳定 `id`、交付文案和 `fact_ids[]`；对话用编号**只映射 `experience[]` 的 bullet**（教育、技能、证书、获奖等模块的列表项不编号），由这些稳定 ID 映射而来。

模块可以因用户选择的岗位或篇幅被排序、隐藏或精简，但不得删除其事实账本记录。只有深度优化且满足弱条目标准时才可删并内容模块。

## 生成纪律

1. 先从账本组装数据，再从数据生成 Markdown 或 PDF；禁止只改某个输出而不更新数据。
2. 姓名、组织、学历与事实账本**逐字一致**；时间类字段保存两份——`原始值`（与账本逐字一致，不改写）与 `展示格式`（按主流程第 2 步统一的写法）。展示格式只能改变书写形式（分隔符、位数、中英月名等），**不得改变日期内容**（数值、起止、在职状态）。PDF 不包含仅用于对话定位的 bullet 编号。
3. 多轮修改只更新受反馈或新确认事实影响的模块。未触及模块保持原有内容和稳定 ID。
4. 用户要求可编辑源数据时，导出 JSON 或 YAML；它是隐私敏感交付物，不自动落盘。
