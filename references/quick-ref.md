# 执行速查卡

> 五步流程的执行索引，不重复规则细节。遇到边界判断回 [SKILL.md](../SKILL.md) 查完整规则。

## 开工前：识别输入

| 检查项 | 动作 |
|---|---|
| 简历素材 | 有 → 提取可引用文本，统称「原文」；图片/附件先本地提取，不可靠则如实说明 |
| 目标岗位/JD | 有 JD 以 JD 为准 → 第 3 步做针对性诊断 |
| 其他参数 | 没给就用缺省（力度=标准、篇幅=一页、格式=Markdown），**不追问** |

## 五步流程

### 第 1 步：结构解析

- 核对六板块：联系方式 / 教育 / 经历 / 技能 / 求职意向 / 可选
- 缺失项**不虚构**，记入「建议补充」
- **前置判断**：联系方式、经历、技能三类中 ≥2 类完全空白 → 不产简历，要求补充
- 敏感字段（身份证/婚况等）→ 提示可移除，不擅自删
- 时间线检查：空档 / 重叠 / 矛盾 → 写入「建议补充」，不编造解释

### 第 2 步：措辞优化

- 删冗词、职责句→成果句、统一时间格式、技能去重排序
- **四条事实红线**（最高优先级）：
  1. 不虚构、不夸大
  2. 数字只搬运不生产（降级：精确数字 > 量级 > 可感知结果 > 删句）
  3. 拿不准保持原样，列入待确认
  4. 面试可辩护——答不上就降格

### 第 3 步：针对性诊断（有岗位信息时）

| 输入 | 动作 |
|---|---|
| 有 JD | 关键词对齐：排序 + 等义换词（保留下位词、标注「JD 关键词对齐」） |
| 只有岗位名称 | 同类内前置，不动用词、不跨板块；标注推断依据 |
| 无岗位信息 | 跳过本步 |

有 JD 时另建 JD 对齐矩阵（[规范](jd-matrix.md)）。

### 第 4 步：草稿自检

- 先扫全部规则，再逐项过 4.1（9 项机械 ✓/✗）+ 4.2（7 项语义 ✓/✗）
- ✗ 项回对应步骤修正后重验
- 末尾附「自检」结论行（4.3）

### 第 5 步：交付

**① 优化后完整简历** + **② 修改说明**（三节固定）

- 经历要点加定位号 `**[N]**`（不用有序列表），初稿从 1 开始依次编号；之后按稳定编号规则维护
- 定位号跨轮稳定：删→留空号、排序→跟着走、合并→保留较小号
- 篇幅默认一页；先按力度允许的范围压缩，仍超页时列出候选项请用户决定

## 关键约束速查

| 约束 | 要点 |
|---|---|
| 事实红线 | 数字只搬运；降级不跳档；面试可辩护 |
| 定位号 | `**[N]**`，只加经历要点，跨轮稳定 |
| 篇幅 | 默认一页，内容问题非排版问题 |
| 排序权限 | 轻度=不动 / 标准=同类内 / 深度=跨板块 |
| 锚点合并 | 保留较小编号，较大废弃不留空号 |
| 事实追溯 | 每条改写可追溯原文；完整账本按需启用 |
| 交付结构 | 已修改 / 建议补充 / 未修改及原因（三节必填） |
| 总体判断 | 仅内容瓶颈时加，三句话，不打分 |
| JD 矩阵 | 仅有 JD 时加，无证据 → 「建议补事实」 |

## 边界 → 替代路径

| 不做 | 替代 |
|---|---|
| 评分/打分 | 深度诊断，指出短板与补救方向 |
| 复杂排版 | 优化内容；排版建议可问 |
| 虚构/扩写 | 组织事实 + 优化措辞 |
| 多版本对比 | 为关键 bullet 提供候选措辞 |
