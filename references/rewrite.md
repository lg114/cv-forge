# 重写规则（锤打成形）

## 职责 → 成果

核心转换：**动作 + 原料 → 结果 + 证据**。

- STAR（情境-任务-行动-结果）用于段落式描述；简历 bullet 用压缩变体：**做了什么（行动）→ 关键决策/难点 → 带来什么（结果）**
- 没有数字时的定性降级路径：精确数字 > 量级（"数万级用户"）> 可感知结果（"xx 流程从天级缩短到小时级"）> 删除
- 量化不只指性能数字：用户量、数据规模、团队规模、迭代次数、覆盖范围、时间节省、故障率下降都是

## 反模板化

检查重写稿：连续 bullets 若开头动词、句式结构雷同，重排。

保留用户原始语气与细节：
- 用户写得糙但有味道的表述（如"一个人扛了整个后端"）→ 精炼但保留质感，不替换成"独立负责后端全部模块的开发与维护"
- 用户的行业黑话/领域细节是真实性的来源，保留

常见中文简历雷区句式（重写时替换）：

| 雷区句式 | 问题 | 处理 |
|---|---|---|
| "负责 xx 的开发和维护" | 只有动作没有结果 | 补结果或技术决策 |
| "参与 xx 项目" | 贡献边界不清 | 写清"我"具体做了什么 |
| "精通 xx" 滥用 | 面试会被任意深挖 | 只用于真能深挖的领域；其余改为"在 xx 场景使用 xx 解决了 xx" |
| "提升了效率/性能" | 无法验证 | 指明哪个环节、从多少到多少 |

## 删减与一页纸压缩

删减优先级（从前往后删）：

1. 与目标岗位无关的经历细节——压缩成一行，不是整段删
2. 重复证明同一能力的 bullets——留最强的一条
3. 教育板块非核心信息（无关课程、低于门槛的绩点）
4. 自我评价——多数是空话，能删则删；保留则每条都要有信息量
5. 项目描述中的技术背景交代——面试官懂的部分不写

压缩原则：**砍 bullet 不砍项目**（项目数量体现广度，bullet 质量体现深度）；先合并同义 bullet，再删低价值 bullet。

## 快车道：单段改写输出格式

1. 改写后版本
2. 一句话说明改了什么、为什么
3. 若缺关键信息，提一个追问（最多一个，不升级成全卷流程）；用户明确表示"别问了，就按现有信息改"时，直接按降级路径处理并在结果中标注"信息不足，建议后续补充"
