# PDF 导出规范

仅当用户明确要求 PDF 时读取并执行本规范；Markdown 仍是默认交付格式。

## 生成前

- 先完成并通过主流程第 4 步的 Markdown 交付草稿自检；PDF 不得成为绕过事实、内容完整性或篇幅取舍规则的途径。
- 使用当前环境可用的 PDF 创建能力；生成、渲染和检查 PDF 时遵循该能力的操作与核验要求。
- 用户未指定视觉偏好时，采用简洁、专业、单栏、ATS 友好的版式：清晰的姓名与联系方式、单一易读字体、稳定的标题层级和留白。不加入照片、图标、图表、评分或装饰性元素。
- 用户给出模板、品牌色或视觉偏好时，可以在不影响可读性、事实边界和 ATS 兼容性的前提下采用；不擅自模拟第三方受版权保护的模板。

## 生成与核验

1. 用通过自检的完整简历生成 PDF，姓名、组织、学历、日期和事实内容须与交付草稿一致；不要将用于对话定位的 bullet 编号印入 PDF。
2. 渲染 PDF 的每一页为图片并进行视觉检查。确认文字未裁切或重叠、字符显示正常、标题与段落层级清楚、页边距和留白一致，且没有占位符或多余空白页。
3. 使用可用的文本提取或 PDF 检查工具复核姓名、联系方式、各段标题和关键日期确实存在。视觉检查不能被文本提取替代。
4. 实际页数以渲染结果为准：若用户指定一页且超页，按主流程的篇幅预算处理，不得以过小字号、过窄边距或压缩行距硬塞。无法在不伤害可读性的前提下满足时，如实说明并交付可读版本。
5. 核验发现问题即修正并重新渲染；未通过视觉核验不得交付 PDF。环境缺少可靠生成或渲染能力时，如实说明，并交付已通过内容自检的 Markdown，不伪称已生成 PDF。

## 隐私与交付

- PDF 及中间文件可能含 PII。最终 PDF 仅通过对话交付或写入用户明确指定、且不在 Git 工作区内的位置。
- 不上传外部简历平台或第三方服务；不在仓库、示例或日志中保留简历内容。
- 交付后清除中间 PDF、渲染图和临时源文件；只保留用户明确要求保存的最终文件。
