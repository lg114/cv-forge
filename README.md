# CV Forge

轻量简历优化 Skill：在**不虚构、不夸大事实**的前提下，优化简历的结构完整性、措辞准确性与岗位针对性，输出改进后的完整简历及结构化修改说明。

规则细节以 [SKILL.md](SKILL.md) 为准，本文件只做导航。SKILL.md 只放**决策规则**（做什么、不做什么、何时触发哪一步），`references/` 放**操作标准**（具体怎么做），同一规则只定义一次、其余位置用链接。

## 核心能力

- **输入**：已成稿的简历，或用户能提供的全部事实（形态不限：纯文本 / Markdown / 要点清单 / 结构化字段）；可选提供目标岗位 / JD、优化力度（轻度 / 标准 / 深度）、语言风格、目标市场、目标篇幅（默认一页）
- **流程**：结构解析与完整性检查 → 措辞优化 → 针对性诊断（有 JD 时附精简对齐矩阵）→ 输出自检 → 生成 Markdown 或 PDF 简历 + 结构化修改说明；追溯方式按复杂度启用，见「数据层」
- **输出**：默认完整优化简历（Markdown，经历要点带 `**[N]**` 定位号）+ 修改说明（逐条「原文 → 改后」对照、为什么改、哪些未动及原因；必要时附一段内容瓶颈的「总体判断」）+ 末尾一行自检结论；明确要求时可交付经渲染核验的 PDF
- **迭代**：基于上一轮结果的多轮修订；补 JD 时按岗位定向（含等义换词、允许定向重排，不增事实），已认可的部分逐字不动
- **可追溯性**：每个改写 bullet 均回链到原文或用户确认的事实；信息不足时最多提出 3 个针对具体经历的高价值待确认问题
- **数据层**：**追溯方式按复杂度启用**——单轮简单简历只在草稿旁标明每句对应的原文，不做形式化建表；多段经历、多轮迭代或 PDF / 源数据交付时才建完整账本与模块化数据，Markdown、PDF 与可选 JSON/YAML 从同一份数据生成，避免多格式漂移
- **自检**：第 4 步内嵌执行——草稿成形后先扫全部规则，再逐条过 4.1 机械复核与 4.2 语义判断两节列出的重点项（是重点，不是全部），结论随输出附上；不打分

## 不做的事

简历评分、岗位匹配打分、排版模板设计、多版本生成、行业深度研究、虚构或扩写内容。

## 安装

1. 克隆或下载本仓库到本地
2. 确认目录结构包含 `SKILL.md` 和 `references/`
3. 将本目录导入为你的 AI 工具的 Skill（具体步骤取决于你使用的工具）

无需额外依赖，无构建步骤。

## 最小使用示例

直接贴出简历正文或事实清单即可；可选附上目标岗位或 JD。例如：

```text
请按以下 JD 优化我的简历，标准力度，目标一页，并导出 PDF。

【简历】
…

【JD】
…
```

未提供岗位信息时，Skill 会先做通用优化，并提示用户可在下一轮补充 JD。

PDF 是显式选择项；未指定时默认输出 Markdown。PDF 使用简洁的单栏版式，并在交付前进行渲染核验，不提供拖拽编辑器或复杂模板设计。

## 使用场景

**场景 1：按 JD 定向优化**
```text
请按以下 JD 优化我的简历，标准力度，目标一页。

【简历】
…（粘贴简历正文）

【JD】
…（粘贴岗位描述）
```

**场景 2：无目标岗位的通用优化**
```text
帮我优化这份简历。（直接粘贴简历正文即可）
```
Skill 会先做通用专业优化，并在末尾提示你可以在下一轮补充 JD。

**场景 3：多轮迭代**
第一轮拿到优化结果后，可以继续提反馈：
```text
第 3 条改成强调团队协作，第 5 条时间写错了，应该是 2023.06
```
Skill 只改你提到的部分，其余内容逐字不动。

**场景 4：导出 PDF**
```text
把优化后的简历导出为 PDF。
```

**场景 5：事实清单代替成稿简历**
```text
以下是我的经历要点，请帮我整理成简历：
- 2022–2024，XX 公司，后端开发
- 负责订单系统重构，QPS 从 500 提升到 2000
…
```

## 常见问题

**Q：我没有完整简历，只有要点清单，能用吗？**
可以。输入形态不限：纯文本、Markdown、要点清单、口述均可，Skill 会从你提供的事实中组织出完整简历。

**Q：Skill 会帮我编造经历或数字吗？**
不会。这是最核心的边界——所有输出内容必须能追溯到你提供的原始素材或你在对话中确认的事实。数字只能搬运，不能生产。

**Q：能给我的简历打分吗？**
不能。简历质量无法压缩成一个有意义的数字。但 Skill 会在发现内容瓶颈时给出「总体判断」，指出短板和补救方向。

**Q：PDF 和 Markdown 有什么区别？**
内容完全一致，区别在交付形式。Markdown 方便你复制粘贴到自己的编辑器；PDF 是经过渲染核验的成品，可直接投递。PDF 使用简洁的单栏版式，不提供复杂排版。

**Q：可以多轮对话修改吗？**
可以。每轮只改你反馈涉及的部分，已确认的内容逐字不动。你可以随时补充 JD、调整力度、修正事实。
